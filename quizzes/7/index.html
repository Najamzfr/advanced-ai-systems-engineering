WEEK 07 / INDEPENDENT ASSESSMENT

Defend your systems judgment.

Eight unseen scenarios. Draft your answers before revealing review criteria. These open-ended answers require self, peer, or instructor review.

Diagnostic quiz

Complete four automatically checked diagnostics, then write your answers to the eight independent scenarios below. The written defenses use a separate review rubric.

Identify the bug

A worker sends an approved notification, then dies before saving completion. What is missing if restart sends it again?

Multi-select

Which should appear in a safe distributed trace?

Sequencing

Order the release path.

Matching

Match task to execution mode.

This page saves drafts and rubric ratings; it does not automatically grade technical reasoning. Score each response 0 (missing/incorrect), 1 (partial), 2 (sound with a gap), or 3 (sound and justified). A suggested readiness threshold is 18/24, with no unresolved authorization or evidence-integrity errors. Ratings are self-reported unless you record an external reviewer.
SCENARIO 01 / 08

A response cache omits policy revision and access scope from its key. Give a correctness and a security failure.

Reveal the review criteria

Stale policy answers/approvals and cross-scope data exposure; partition keys and invalidate correctly or avoid unsafe caching.

Review unit 7-1: Production request and data boundaries →

SCENARIO 02 / 08

A webhook is acknowledged before its job is committed. The process crashes between those events. What is lost?

Reveal the review criteria

Sender may consider delivery complete while no durable job exists; commit accepted state before acknowledgement and deduplicate by stable event identity.

Review unit 7-2: Events, checkpoints, and durable execution →

SCENARIO 03 / 08

A poison event consumes every retry slot and blocks newer jobs. Design dead-letter and replay behavior.

Reveal the review criteria

Classify nonretryable errors, cap attempts/age, quarantine with reason/version, alert, repair before controlled replay with original event identity; protect fairness.

Review unit 7-2: Events, checkpoints, and durable execution →

SCENARIO 04 / 08

A worker commits a database update and then fails before publishing the event. How does an outbox change the failure boundary?

Reveal the review criteria

Commit state and publish intent atomically; dispatcher retries durable intent using stable effect key; still require sink dedup/status for crash-after-effect.

Review unit 7-3: Outbox, idempotency, and compensation →

SCENARIO 05 / 08

A compensating refund also times out. Can you mark the original operation undone?

Reveal the review criteria

No; compensation is another uncertain effect with its own identity/status; reconcile and expose pending/unknown state, preserve audit and operator path.

Review unit 7-3: Outbox, idempotency, and compensation →

SCENARIO 06 / 08

A trace shows API 50ms, queue wait 9s, model 700ms, tool 100ms. Where should the first performance experiment focus?

Reveal the review criteria

Queue/admission/capacity dominates; trace boundaries must include waiting; measure arrival/load and worker capacity rather than optimizing a minor component first.

Review unit 7-4: OpenTelemetry across asynchronous work →

SCENARIO 07 / 08

A 99.5% SLO covers 20,000 eligible tasks. After 85 failures, how much failure budget remains and does it permit unauthorized actions?

Reveal the review criteria

100 failures allowed, 15 remain; window/denominator must be defined; security prohibitions are separate and not purchasable with error budget.

Review unit 7-5: SLIs, SLOs, canaries, and rollback →

SCENARIO 08 / 08

Rollback restores old code that cannot parse new approval records. Design a release compatibility check.

Reveal the review criteria

Version schemas/policies, support backward-compatible reads or explicit migration, test pending workflow resume/approval binding and rollback before release.
