LAB 3B / WEEK 03

MCP Client + MCP Server

Build an MCP server and a client that distrusts malformed capabilities and responses.

Objective

Build an MCP server and a client that distrusts malformed capabilities and responses.

Prerequisites

Lab 3A; MCP pinned specification; Python SDK; local transport.

Review Week 03 →

Architecture

Canonical lab brief

Server tools:

search_documents()
fetch_document()
calculate_metric()
store_result()

Client should:

  • discover tools
  • inspect schemas
  • invoke tools
  • validate responses
  • reject malformed output
  • handle failures

Implementation steps

  1. Step 01

    Expose search_documents, fetch_document, calculate_metric, and store_result with explicit input and output contracts.

  2. Step 02

    Connect a client, initialize capabilities, discover tools, and inspect schemas before invocation.

  3. Step 03

    Validate returned data against application contracts; record request identity, server identity, elapsed time, and result status.

  4. Step 04

    Constrain document access and storage paths; require an authorization decision for every operation. Treat calculations as deterministic functions.

  5. Step 05

    Inject protocol errors, incompatible schemas, server disconnects, and malicious returned text. Verify that the client fails safely.

Experiment requirements

Test discovery, valid invocation, missing capability, invalid arguments, malformed output, and repeated store_result with the same operation key.

Record dataset and code revisions, seeds, configuration, hardware, and per-case outcomes. Freeze test data before selecting the winning configuration. Report missing or blocked runs honestly.

Metrics

Contract pass rate; unauthorized-call rejection; duplicate-effect count; invocation latency; recovery rate.

Publish denominators and per-slice results. Use paired comparisons and uncertainty estimates where outcomes are stochastic.

Failure cases

Untrusted server description; malformed output; path traversal; tool spoofing; disconnect after storage succeeds.

Deliverables

Server, client, schemas, permission matrix, integration fixtures, and an MCP sequence diagram.

Stretch goals

Add Streamable HTTP and document transport-specific authorization and session behavior.
