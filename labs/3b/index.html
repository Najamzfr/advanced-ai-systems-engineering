LAB 3B / WEEK 03

MCP Client + MCP Server

Build an MCP server and a client that distrusts malformed capabilities and responses.

Objective

Build an MCP server and a client that distrusts malformed capabilities and responses.

Prerequisites and starting inputs

Lab 3A; MCP pinned specification; Python SDK; local transport.

Finish the final learning unit for Week 3, then run the starter fixtures. Preserve the preceding week's artifact and configuration.

Architecture

Warm-up diagnostic

search_documents returns a valid-looking passage followed by an instruction to invoke delete_document. The client was granted read-only access.

Choose the correct containment controls.

Diagnostic hint

What did the user actually authorize?

Diagnostic reasoning

Keep the response as evidence, validate its contract, and deny deletion before execution.

This browser check validates the stated fixture rule, not completion of the implementation lab.

Guided implementation path

Starting artifact: the final unit of Week 3 and the preceding week's versioned experiment/state contracts. Download and run the engineering fixtures →

Use Python 3.10+ for the standard-library fixtures. Live model, framework, MCP and GPU experiments require separately pinned dependencies and declared hardware/provider access. Keep deterministic fixture results separate from real measurements.

CHECKPOINT 1 / 5 · WORKED START

Establish the input contract

Pin the MCP specification and SDK version. Implement a local stdio server with one search tool, one resource and one prompt.

Expected intermediate result
Server starts with protocol-only stdout and diagnostics on stderr.
Stuck? Inspect this boundary

The starter contract fixture is not a protocol server; use the actual pinned MCP implementation.

CHECKPOINT 2 / 5 · GUIDED BUILD

Implement and inspect

Create a host/client connection, initialize, discover capabilities, call the tool and fetch a resource.

Expected intermediate result
A recorded round trip identifies host, client and server responsibilities and typed results.
Stuck? Inspect this boundary

Check initialization/version negotiation before debugging a tool-specific error.

CHECKPOINT 3 / 5 · GUIDED BUILD

Implement and inspect

Enforce per-request identity/scope, real-path containment and result validation. Test an unknown source and a symlink escape.

Expected intermediate result
Denied requests expose no forbidden content; roots alone are not treated as enforcement.
Stuck? Inspect this boundary

Resolve actual paths and inspect server filesystem permissions, not just a string prefix.

CHECKPOINT 4 / 5 · INDEPENDENT TRANSFER

Implement and inspect

Exercise StreamableHTTP in a local network setup or document the exact authenticated remote contract; test disconnect, malformed response and timeout.

Expected intermediate result
Transport errors and tool errors remain distinct, and secrets stay out of prompts/logs.
Stuck? Inspect this boundary

Record what was executed versus designed. A transport design does not prove a remote deployment.

CHECKPOINT 5 / 5 · INDEPENDENT TRANSFER

Produce the evidence

Connect the host to the Week 2 search/fetch adapter and attach trace IDs.

Expected intermediate result
A research request returns cited evidence or an explicit incomplete/denied result through MCP.
Stuck? Inspect this boundary

Discovery grants no permission; retain server-side authorization even when the host filters tools.

Required experiments

Server tools:

search_documents()
fetch_document()
calculate_metric()
store_result()

Client should:

  • discover tools
  • inspect schemas
  • invoke tools
  • validate responses
  • reject malformed output
  • handle failures

Test discovery, valid invocation, missing capability, invalid arguments, malformed output, and repeated store_result with the same operation key.

Metrics and interpretation

Contract pass rate; unauthorized-call rejection; duplicate-effect count; invocation latency; recovery rate.

Preserve per-case outcomes, denominators, model/data/configuration revisions, run mode, paired comparisons and uncertainty. Separate deterministic fixtures from live measurements.

Failure cases

Untrusted server description; malformed output; path traversal; tool spoofing; disconnect after storage succeeds.

Deliverables

Server, client, schemas, permission matrix, integration fixtures, and an MCP sequence diagram.

Include every guided checkpoint, raw experiment results, failed cases, a decision memo and reproduction instructions.

Stretch goals

Add Streamable HTTP and document transport-specific authorization and session behavior.

Extra scale, frameworks and sweeps follow the required experiment; they do not replace it.
