LAB 3A / WEEK 03

Build Your Own Agent Runtime

Implement a bounded agent runtime before recreating it with a framework.

Objective

Implement a bounded agent runtime before recreating it with a framework.

Prerequisites and starting inputs

Labs 1–2; typed Python models; isolated tool fixtures.

Finish the final learning unit for Week 3, then run the starter fixtures. Preserve the preceding week's artifact and configuration.

Architecture

Warm-up diagnostic

A loop retries forever on timeout. Each retry receives a new operation key and successful calls alone decrement the step counter.

Select repairs that address the observed faults.

Diagnostic hint

There are separate effect, termination, and policy invariants.

Diagnostic reasoning

Use stable effect keys, count every attempt, enforce a deadline, authorize actions, and persist observations.

This browser check validates the stated fixture rule, not completion of the implementation lab.

Guided implementation path

Starting artifact: the final unit of Week 3 and the preceding week's versioned experiment/state contracts. Download and run the engineering fixtures →

Use Python 3.10+ for the standard-library fixtures. Live model, framework, MCP and GPU experiments require separately pinned dependencies and declared hardware/provider access. Keep deterministic fixture results separate from real measurements.

CHECKPOINT 1 / 5 · WORKED START

Establish the input contract

Run python coursekit.py contracts; implement a scripted model that emits a search action, fetch action and final result.

Expected intermediate result
Contract outcomes are OK, DENIED_SCOPE and SCHEMA_ERROR; the loop produces a complete deterministic trace.
Stuck? Inspect this boundary

A scripted model is a harness fixture, not evidence of live agent competence.

CHECKPOINT 2 / 5 · GUIDED BUILD

Implement and inspect

Define typed decision and observation unions; implement schema, scope, timeout, stop, repeated-action and global budget gates.

Expected intermediate result
Invalid decisions never execute; exhausted runs end with explicit incomplete status.
Stuck? Inspect this boundary

Count hidden retries and nested calls in the same global budget.

CHECKPOINT 3 / 5 · GUIDED BUILD

Implement and inspect

Add a write-like evidence tool with a stable effect key and simulated crash-after-effect.

Expected intermediate result
Retry returns the existing effect; attempts have separate trace IDs.
Stuck? Inspect this boundary

Do not generate an idempotency key per transport attempt.

CHECKPOINT 4 / 5 · INDEPENDENT TRANSFER

Implement and inspect

Run the same flow with the chosen real model, then port it to one framework.

Expected intermediate result
Scratch and framework traces preserve the same permissions, budgets and error semantics.
Stuck? Inspect this boundary

Inspect automatic retries, parallel tool calls and schema coercion in framework defaults.

CHECKPOINT 5 / 5 · INDEPENDENT TRANSFER

Produce the evidence

Measure task/tool/argument success, steps, recovery, latency and cost on held-out normal and failure cases.

Expected intermediate result
A comparison report explains when dynamic action choice adds value over a workflow.
Stuck? Inspect this boundary

Successful final text does not erase an unauthorized intermediate action.

Required experiments

Implement from scratch:

while budget_available:
    context = build_context(state)
    decision = model(context)
    action = validate(decision)
    observation = execute(action)
    state.update(observation)

    if complete(state):
        break

Add:

  • max steps
  • timeout
  • retry
  • structured state
  • validation
  • tool failures
  • human escalation

Then recreate the same system with:

  • PydanticAI or
  • another lightweight agent framework

Compare scratch and framework implementations on success, malformed decisions, loops, timeouts, and ambiguous side-effect outcomes.

Metrics and interpretation

Task success; tool and argument accuracy; steps; retries; recovery; latency; tokens; escalation rate.

Preserve per-case outcomes, denominators, model/data/configuration revisions, run mode, paired comparisons and uncertainty. Separate deterministic fixtures from live measurements.

Failure cases

Infinite loop; invalid arguments; execution after budget exhaustion; duplicate effect; lost state; retry storm.

Deliverables

Both implementations, typed state, trace fixtures, failure tests, and a framework trade-off ADR.

Include every guided checkpoint, raw experiment results, failed cases, a decision memo and reproduction instructions.

Stretch goals

Persist checkpoints and replay a run without re-executing completed side effects.

Extra scale, frameworks and sweeps follow the required experiment; they do not replace it.
