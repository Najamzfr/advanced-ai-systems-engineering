LAB 1 / WEEK 01

LLM Behavioral Test Bench

Freeze a behavioral benchmark and compare at least two models.

Objective

Freeze a behavioral benchmark and compare at least two models.

Prerequisites

Python; typed API adapters; basic statistics; a local model or existing model access.

Review Week 01 →

Architecture

Canonical lab brief

Build:

model-bench/
├── datasets/
├── evaluators/
├── providers/
├── experiments/
├── reports/
└── tests/

Compare at least two models.

Measure:

  • factual correctness
  • instruction following
  • structured-output validity
  • reasoning consistency
  • long-context degradation
  • latency
  • token usage
  • judge score

Implementation steps

  1. Step 01

    Create a versioned JSONL dataset with id, category, input, expected behavior, and provenance. Separate development and held-out cases before tuning.

  2. Step 02

    Implement provider adapters returning text, parsed output, latency, token counts, model revision, and error category. Keep a deterministic mock for contract tests.

  3. Step 03

    Add exact, schema, functional, and judge evaluators. Calibrate judge decisions on a human-reviewed subset and randomize response order.

  4. Step 04

    Run both models across factual, instruction, structured-output, reasoning, and long-context cases. Repeat stochastic configurations and retain per-example outputs.

  5. Step 05

    Bootstrap paired task-level differences; publish slice counts, confidence intervals, p50/p95 latency, and cost assumptions. Test malformed and unavailable-provider responses.

Experiment requirements

Vary temperature, evidence position, and response order independently. Compare judged and human-labeled outcomes; distinguish simulated contract tests from real model runs.

Record dataset and code revisions, seeds, configuration, hardware, and per-case outcomes. Freeze test data before selecting the winning configuration. Report missing or blocked runs honestly.

Metrics

Factual correctness; instruction following; schema validity; reasoning consistency; long-context degradation; latency; tokens; judge score.

Publish denominators and per-slice results. Use paired comparisons and uncertainty estimates where outcomes are stochastic.

Failure cases

Judge order sensitivity; invalid JSON; provider timeout; empty answer; contamination; cost calculated without retries.

Deliverables

Raw runs, evaluation dataset, adapters, automated checks, calibrated judge report, and reproducible README.

Stretch goals

Add a sequential drift detector and estimate its false-alarm rate on unchanged model runs.
