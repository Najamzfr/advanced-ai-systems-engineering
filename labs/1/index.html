LAB 1 / WEEK 01

LLM Behavioral Test Bench

Freeze a behavioral benchmark and compare at least two models.

Objective

Freeze a behavioral benchmark and compare at least two models.

Prerequisites and starting inputs

Python; typed API adapters; basic statistics; a local model or existing model access.

Finish the final learning unit for Week 1, then run the starter fixtures. Preserve the preceding week's artifact and configuration.

Architecture

Warm-up diagnostic

The prompt author inspects all held-out answers, adds three examples from them, then reports a 12-point improvement.

Select the required repairs.

Diagnostic hint

Which cases have already influenced the candidate?

Diagnostic reasoning

Use a new untouched holdout, retain the old cases as development, and rerun the paired comparison with versioned artifacts.

This browser check validates the stated fixture rule, not completion of the implementation lab.

Guided implementation path

Starting artifact: the final unit of Week 1 and the preceding week's versioned experiment/state contracts. Download and run the engineering fixtures →

Use Python 3.10+ for the standard-library fixtures. Live model, framework, MCP and GPU experiments require separately pinned dependencies and declared hardware/provider access. Keep deterministic fixture results separate from real measurements.

CHECKPOINT 1 / 5 · WORKED START

Establish the input contract

Run the starter fixture and define Case(id, input, expected, slice, split) plus Run(model, prompt, config, mode). Add 12 development cases across factual, format, reasoning, and missing-answer behavior.

Expected intermediate result
Every case has an expected outcome; replay and real inference are labeled separately.
Stuck? Inspect this boundary

If scores cannot be reproduced, inspect dataset/evaluator revisions before changing the model.

CHECKPOINT 2 / 5 · GUIDED BUILD

Implement and inspect

Implement one provider adapter and a deterministic replay adapter behind the same interface; add a second real model for the required comparison.

Expected intermediate result
Common output includes raw response, timing, token usage, errors and version. At least two models appear in the final benchmark.
Stuck? Inspect this boundary

Do not treat a replay adapter as the second model. A blocked model run remains unexecuted.

CHECKPOINT 3 / 5 · GUIDED BUILD

Implement and inspect

Implement exact/schema/functional checks, then annotate a human subset and calibrate a judge. Swap answer order.

Expected intermediate result
Per-case metrics remain separate; judge confusion counts and order flips are visible.
Stuck? Inspect this boundary

A single composite score hides whether the problem is formatting, support, or biased measurement.

CHECKPOINT 4 / 5 · INDEPENDENT TRANSFER

Implement and inspect

Vary decoding and evidence position under fixed conditions. Run paired comparisons and uncertainty estimates by independent case/source.

Expected intermediate result
Results contain repeated trials, long-context positions, slice denominators, p50/p95, tokens and cost.
Stuck? Inspect this boundary

Keep output lengths and model revision fixed when testing evidence position.

CHECKPOINT 5 / 5 · INDEPENDENT TRANSFER

Produce the evidence

Freeze held-out cases, run the final comparison, and write the 500,000-query/month RFC with three deployment strategies.

Expected intermediate result
A clean command regenerates the report; raw outputs and decisions are versioned.
Stuck? Inspect this boundary

Three strategies may include routing/fallback; they do not replace the required two-model benchmark.

Required experiments

Build:

model-bench/
├── datasets/
├── evaluators/
├── providers/
├── experiments/
├── reports/
└── tests/

Compare at least two models.

Measure:

  • factual correctness
  • instruction following
  • structured-output validity
  • reasoning consistency
  • long-context degradation
  • latency
  • token usage
  • judge score

Vary temperature, evidence position, and response order independently. Compare judged and human-labeled outcomes; distinguish simulated contract tests from real model runs.

Metrics and interpretation

Factual correctness; instruction following; schema validity; reasoning consistency; long-context degradation; latency; tokens; judge score.

Preserve per-case outcomes, denominators, model/data/configuration revisions, run mode, paired comparisons and uncertainty. Separate deterministic fixtures from live measurements.

Failure cases

Judge order sensitivity; invalid JSON; provider timeout; empty answer; contamination; cost calculated without retries.

Deliverables

Raw runs, evaluation dataset, adapters, automated checks, calibrated judge report, and reproducible README.

Include every guided checkpoint, raw experiment results, failed cases, a decision memo and reproduction instructions.

Stretch goals

Add a sequential drift detector and estimate its false-alarm rate on unchanged model runs.

Extra scale, frameworks and sweeps follow the required experiment; they do not replace it.
