LAB 6A / WEEK 06

Adaptation Study

Compare adaptation strategies with one common evaluation harness.

Objective

Compare adaptation strategies with one common evaluation harness.

Prerequisites

Lab 1 harness; licensed dataset; a trainable small model; local GPU or available free compute.

Review Week 06 →

Architecture

Canonical lab brief

Compare:

  1. zero-shot
  2. few-shot
  3. advanced prompt
  4. RAG
  5. LoRA
  6. LoRA + RAG

Use one common evaluation harness.

Implementation steps

  1. Step 01

    Define the target behavior and split data by source or time. Deduplicate across all splits and retain provenance.

  2. Step 02

    Build zero-shot, few-shot, advanced-prompt, and RAG baselines against the same held-out tasks.

  3. Step 03

    Train a LoRA adapter with recorded base model, rank, target modules, seeds, steps, data revision, and precision.

  4. Step 04

    Evaluate LoRA alone and LoRA plus RAG. Include unrelated tasks to expose forgetting and temporal cases to test changing knowledge.

  5. Step 05

    Publish quality and compute trade-offs; keep test data out of adapter and prompt selection.

Experiment requirements

Compare all six strategies. Vary adapter rank or data quantity once; include a contamination check and a capability-retention set.

Record dataset and code revisions, seeds, configuration, hardware, and per-case outcomes. Freeze test data before selecting the winning configuration. Report missing or blocked runs honestly.

Metrics

Task quality; groundedness; schema validity; retention; training time; peak memory; inference latency; tokens.

Publish denominators and per-slice results. Use paired comparisons and uncertainty estimates where outcomes are stochastic.

Failure cases

Data leakage; synthetic label errors; forgetting; stale factual knowledge; out-of-memory; unsupported numerical claims.

Deliverables

Dataset manifest, six configurations, training script, adapter metadata, raw evaluations, and decision memo.

Stretch goals

Compare QLoRA with LoRA under the same memory and evaluation constraints. If hardware is unavailable, record the blocked experiment; do not label simulations as training results.
