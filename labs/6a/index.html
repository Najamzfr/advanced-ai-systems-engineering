LAB 6A / WEEK 06

Adaptation Study

Compare adaptation strategies with one common evaluation harness.

Objective

Compare adaptation strategies with one common evaluation harness.

Prerequisites and starting inputs

Lab 1 harness; licensed dataset; a trainable small model; local GPU or available free compute.

Finish the final learning unit for Week 6, then run the starter fixtures. Preserve the preceding week's artifact and configuration.

Warm-up diagnostic

Diagnostic hint

Diagnostic reasoning

This browser check validates the stated fixture rule, not completion of the implementation lab.

Guided implementation path

Starting artifact: the final unit of Week 6 and the preceding week's versioned experiment/state contracts. Download and run the engineering fixtures →

Use Python 3.10+ for the standard-library fixtures. Live model, framework, MCP and GPU experiments require separately pinned dependencies and declared hardware/provider access. Keep deterministic fixture results separate from real measurements.

CHECKPOINT 1 / 5 · WORKED START

Establish the input contract

Freeze task, retention and held-out splits; create a dataset card and near-duplicate audit.

Expected intermediate result
No generated variants cross source splits; provenance and label policy are explicit.
Stuck? Inspect this boundary

More examples can reproduce the same teacher error; audit coverage and label quality.

CHECKPOINT 2 / 5 · GUIDED BUILD

Implement and inspect

Run zero-shot, few-shot, advanced prompting and RAG using one harness and fixed model/budgets.

Expected intermediate result
Four baseline rows with per-case quality, cost, latency and grounding.
Stuck? Inspect this boundary

Define advanced prompting concretely and choose examples only on development data.

CHECKPOINT 3 / 5 · GUIDED BUILD

Implement and inspect

Train one bounded LoRA/QLoRA adapter on a feasible model and log all memory/training assumptions.

Expected intermediate result
Adapter configuration, training/validation curves, held-out and retention scores.
Stuck? Inspect this boundary

Frozen quantized weights still leave activations and optimizer/adapter memory.

CHECKPOINT 4 / 5 · INDEPENDENT TRANSFER

Implement and inspect

Run LoRA and LoRA+RAG, completing the required six-way matrix.

Expected intermediate result
Six conditions with training/inference cost, retention and update burden.
Stuck? Inspect this boundary

Hardware-blocked runs are labeled unexecuted; trace analysis is a separate evidence mode.

CHECKPOINT 5 / 5 · INDEPENDENT TRANSFER

Produce the evidence

Select a technique by failure mechanism and measured gains, then integrate it only if justified.

Expected intermediate result
Decision table and reproducible artifacts; negative findings are retained.
Stuck? Inspect this boundary

Do not hide forgetting or unsupported claims behind aggregate task improvement.

Required experiments

Compare:

  1. zero-shot
  2. few-shot
  3. advanced prompt
  4. RAG
  5. LoRA
  6. LoRA + RAG

Use one common evaluation harness.

Compare all six strategies. Vary adapter rank or data quantity once; include a contamination check and a capability-retention set.

The six-way adaptation study and one executed serving optimization remain required. A blocked hardware run is recorded as unexecuted; trace analysis does not establish practical execution.

Metrics and interpretation

Task quality; groundedness; schema validity; retention; training time; peak memory; inference latency; tokens.

Preserve per-case outcomes, denominators, model/data/configuration revisions, run mode, paired comparisons and uncertainty. Separate deterministic fixtures from live measurements.

Failure cases

Data leakage; synthetic label errors; forgetting; stale factual knowledge; out-of-memory; unsupported numerical claims.

Deliverables

Dataset manifest, six configurations, training script, adapter metadata, raw evaluations, and decision memo.

Include every guided checkpoint, raw experiment results, failed cases, a decision memo and reproduction instructions.

Stretch goals

Compare QLoRA with LoRA under the same memory and evaluation constraints. If hardware is unavailable, record the blocked experiment; do not label simulations as training results.

Extra scale, frameworks and sweeps follow the required experiment; they do not replace it.
