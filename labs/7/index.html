LAB 7 / WEEK 07

Durable AI Workflow

Recover a durable AI workflow after failures without duplicating effects.

Objective

Recover a durable AI workflow after failures without duplicating effects.

Prerequisites and starting inputs

Lab 3 tools; persistent database; queue; Docker basics; OpenTelemetry.

Finish the final learning unit for Week 7, then run the starter fixtures. Preserve the preceding week's artifact and configuration.

Architecture

Warm-up diagnostic

API span ends after enqueue. Worker logs have unrelated request IDs; model and tool spans have no links. Duplicate delivery sends twice.

Select platform repairs.

Diagnostic hint

Observability and effect correctness are different concerns.

Diagnostic reasoning

Propagate safe trace metadata, persist checkpoints, and reconcile effects by stable keys; redact sensitive fields.

This browser check validates the stated fixture rule, not completion of the implementation lab.

Guided implementation path

Starting artifact: the final unit of Week 7 and the preceding week's versioned experiment/state contracts. Download and run the engineering fixtures →

Use Python 3.10+ for the standard-library fixtures. Live model, framework, MCP and GPU experiments require separately pinned dependencies and declared hardware/provider access. Keep deterministic fixture results separate from real measurements.

CHECKPOINT 1 / 5 · WORKED START

Establish the input contract

Run python coursekit.py durable; design persistent jobs, approval and outbox schemas for the sandbox campaign.

Expected intermediate result
Fixture shows one logical dispatch; real schema has event/effect uniqueness and policy versions.
Stuck? Inspect this boundary

The in-memory example illustrates reconciliation, not a distributed durability guarantee.

CHECKPOINT 2 / 5 · GUIDED BUILD

Implement and inspect

Implement event acceptance, checkpoints, bounded retries, approval waits and dead-letter handling.

Expected intermediate result
Duplicate events map to the same job; restart resumes with exact action and expiry intact.
Stuck? Inspect this boundary

Persist accepted work before acknowledging the input event.

CHECKPOINT 3 / 5 · GUIDED BUILD

Implement and inspect

Use a separate sandbox sink with deduplication/status lookup and inject crash-after-effect.

Expected intermediate result
One logical sink effect and an eventually reconciled outbox state.
Stuck? Inspect this boundary

Local atomicity alone cannot resolve an unknown external effect.

CHECKPOINT 4 / 5 · INDEPENDENT TRANSFER

Implement and inspect

Add OpenTelemetry spans across API, queue, worker, model and tools; redact sensitive payloads.

Expected intermediate result
A complete trace includes queue delay, tokens, policy decisions and errors; metric labels remain bounded.
Stuck? Inspect this boundary

Use context propagation/span links rather than unrelated trace IDs at every service.

CHECKPOINT 5 / 5 · INDEPENDENT TRANSFER

Produce the evidence

Deploy locally, run canary/replay gates, restart dependencies, and demonstrate rollback.

Expected intermediate result
Runbook, health checks, SLI/SLO definitions, recovery evidence and state-compatible rollback.
Stuck? Inspect this boundary

An endpoint returning 200 does not prove the queued task completed.

System must recover correctly.

Inject service failure, duplicate event, timeout, and process restart. Prove recovery with the same event identity and no duplicate notification.

Metrics and interpretation

Recovery time; duplicate effects; retry count; dead-letter count; end-to-end latency; approval age; trace coverage.

Preserve per-case outcomes, denominators, model/data/configuration revisions, run mode, paired comparisons and uncertainty. Separate deterministic fixtures from live measurements.

Failure cases

Lost acknowledgement; stale approval; crash after side effect; poison event; orphan checkpoint; missing trace context.

Deliverables

Runnable workflow, persistence schema, fault fixtures, traces, recovery report, and Compose configuration.

Include every guided checkpoint, raw experiment results, failed cases, a decision memo and reproduction instructions.

Stretch goals

Add compensation for a reversible operation and distinguish its business semantics from retry.

Extra scale, frameworks and sweeps follow the required experiment; they do not replace it.
