LAB 7 / WEEK 07

Durable AI Workflow

Recover a durable AI workflow after failures without duplicating effects.

Objective

Recover a durable AI workflow after failures without duplicating effects.

Prerequisites

Lab 3 tools; persistent database; queue; Docker basics; OpenTelemetry.

Review Week 07 →

Architecture

Canonical lab brief

Build:

Scheduled / Event Trigger
        ↓
       Queue
        ↓
   Data Ingestion
        ↓
Deterministic Validation
        ↓
       Agent
        ↓
 Verification
        ↓
 Human Approval
        ↓
 External Action
        ↓
 Audit Trail

Inject:

  • service failure
  • duplicate event
  • timeout
  • process restart

System must recover correctly.

Implementation steps

  1. Step 01

    Define event IDs, state machine, persistent checkpoints, retries, compensation, and a dead-letter policy.

  2. Step 02

    Connect scheduled and event triggers to a queue, ingestion, deterministic validation, agent investigation, and verification.

  3. Step 03

    Bind approval to the exact proposed action and its digest. Expire approvals and invalidate them after any action change.

  4. Step 04

    Commit an action intent, invoke an idempotent sink, and reconcile unknown outcomes before retries. Append an audit record.

  5. Step 05

    Propagate trace context across worker boundaries. Kill and restart the worker around each checkpoint and external effect.

Experiment requirements

Inject service failure, duplicate event, timeout, and process restart. Prove recovery with the same event identity and no duplicate notification.

Record dataset and code revisions, seeds, configuration, hardware, and per-case outcomes. Freeze test data before selecting the winning configuration. Report missing or blocked runs honestly.

Metrics

Recovery time; duplicate effects; retry count; dead-letter count; end-to-end latency; approval age; trace coverage.

Publish denominators and per-slice results. Use paired comparisons and uncertainty estimates where outcomes are stochastic.

Failure cases

Lost acknowledgement; stale approval; crash after side effect; poison event; orphan checkpoint; missing trace context.

Deliverables

Runnable workflow, persistence schema, fault fixtures, traces, recovery report, and Compose configuration.

Stretch goals

Add compensation for a reversible operation and distinguish its business semantics from retry.
