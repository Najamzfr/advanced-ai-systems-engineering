LAB 4 / WEEK 04

Is Multi-Agent Actually Better?

Determine whether coordination earns its complexity on the same research task.

Objective

Determine whether coordination earns its complexity on the same research task.

Prerequisites

Labs 1–3; evidence corpus; Project 1 evaluation questions.

Review Week 04 →

Architecture

Canonical lab brief

Implement the same task three times:

Version A

Single agent

Version B

Planner → executor

Version C

Supervisor + specialist agents

Measure:

  • success rate
  • latency
  • number of model calls
  • token usage
  • errors
  • reproducibility
  • debugging complexity

Students must justify which architecture should be deployed.

Implementation steps

  1. Step 01

    Freeze tasks, models, evidence access, stop criteria, and a common token budget.

  2. Step 02

    Build a single-agent baseline with the same tools used in every later variant.

  3. Step 03

    Build planner–executor with typed task dependencies and explicit verification; allow bounded replanning.

  4. Step 04

    Build supervisor plus specialists with isolated contexts and structured evidence handoffs.

  5. Step 05

    Run repeated paired evaluations. Categorize coordination failures and choose a deployment architecture based on evidence.

Experiment requirements

Compare all three architectures at equal budgets. Ablate verification and shared memory separately; include contradictory evidence and one failed worker.

Record dataset and code revisions, seeds, configuration, hardware, and per-case outcomes. Freeze test data before selecting the winning configuration. Report missing or blocked runs honestly.

Metrics

Success rate; latency; model calls; tokens; errors; reproducibility; debugging complexity.

Publish denominators and per-slice results. Use paired comparisons and uncertainty estimates where outcomes are stochastic.

Failure cases

Cascading errors; duplicated work; conflicting claims; deadlock; missing worker result; unbounded delegation.

Deliverables

Three runnable variants, paired result table, failure traces, and a justified deployment decision.

Stretch goals

Plot a quality–cost frontier across task difficulty and identify a routing policy.
