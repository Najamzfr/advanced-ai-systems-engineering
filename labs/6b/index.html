LAB 6B / WEEK 06

Inference Benchmark

Measure serving behavior as concurrency and optimization change.

Objective

Measure serving behavior as concurrency and optimization change.

Prerequisites and starting inputs

Lab 6A model or another permitted small model; vLLM-compatible hardware for its serving path.

Finish the final learning unit for Week 6, then run the starter fixtures. Preserve the preceding week's artifact and configuration.

Architecture

Warm-up diagnostic

A trace shows queue=850 ms, prefill=400 ms, first decode=50 ms, remaining decode=1,100 ms.

Predict TTFT and total latency.

Diagnostic hint

Start the clock at request arrival.

Diagnostic reasoning

TTFT=850+400+50=1,300 ms. Total=1,300+1,100=2,400 ms; a two-second completion SLO is breached.

This browser check validates the stated fixture rule, not completion of the implementation lab.

Guided implementation path

Starting artifact: the final unit of Week 6 and the preceding week's versioned experiment/state contracts. Download and run the engineering fixtures →

Use Python 3.10+ for the standard-library fixtures. Live model, framework, MCP and GPU experiments require separately pinned dependencies and declared hardware/provider access. Keep deterministic fixture results separate from real measurements.

CHECKPOINT 1 / 5 · WORKED START

Establish the input contract

Run python coursekit.py kv, then inspect your selected model's layers, KV heads, head size and precision.

Expected intermediate result
Illustrative fixture is 512 MiB/sequence; your model has a separately calculated estimate.
Stuck? Inspect this boundary

Query heads and KV heads differ under grouped-query attention.

CHECKPOINT 2 / 5 · GUIDED BUILD

Implement and inspect

Serve one model in a declared hardware environment; warm up and record a baseline length/concurrency workload.

Expected intermediate result
Measured TTFT, inter-token latency, completion p50/p95, throughput, memory and errors.
Stuck? Inspect this boundary

Separate warmup, queueing and steady state; fixture arithmetic is not a GPU benchmark.

CHECKPOINT 3 / 5 · GUIDED BUILD

Implement and inspect

Execute one optimization: continuous batching settings, prefix caching, quantization or another supported feature.

Expected intermediate result
Matched baseline/optimized runs retain the same quality workload.
Stuck? Inspect this boundary

Record actual runtime/kernel support instead of assuming a tutorial version matches your machine.

CHECKPOINT 4 / 5 · INDEPENDENT TRANSFER

Implement and inspect

Test saturation and one quality-sensitive slice; record cancellations, timeouts and tail behavior.

Expected intermediate result
A throughput/latency trade-off and a quality non-regression result.
Stuck? Inspect this boundary

Maximum GPU utilization can coexist with missed user latency targets.

CHECKPOINT 5 / 5 · INDEPENDENT TRANSFER

Produce the evidence

Write the 100 requests/s, p95<2s capacity proposal with defined response boundary and headroom.

Expected intermediate result
Executed capacity is separated from extrapolation; hardware-blocked skills remain unverified.
Stuck? Inspect this boundary

Little's Law uses averages and cannot prove p95 by multiplying a target.

Compare baseline and optimized serving under steady load and bursts. Report cache hit and miss cases separately.

The six-way adaptation study and one executed serving optimization remain required. A blocked hardware run is recorded as unexecuted; trace analysis does not establish practical execution.

Metrics and interpretation

Throughput; TTFT; tokens/sec; p50/p95/p99 completion latency; concurrency; peak memory; error rate.

Preserve per-case outcomes, denominators, model/data/configuration revisions, run mode, paired comparisons and uncertainty. Separate deterministic fixtures from live measurements.

Failure cases

OOM; queue buildup; cache contamination; cold starts; long requests starving short requests; dropped requests.

Deliverables

Load generator, hardware manifest, latency distributions, optimization comparison, and capacity assumptions.

Include every guided checkpoint, raw experiment results, failed cases, a decision memo and reproduction instructions.

Stretch goals

Compare open-loop arrival generation with closed-loop clients to expose coordinated omission.

Extra scale, frameworks and sweeps follow the required experiment; they do not replace it.
