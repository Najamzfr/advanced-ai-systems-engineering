LAB 2 / WEEK 02

RAG Architecture Challenge

Find which retrieval change improves evidence coverage and final answers.

Objective

Find which retrieval change improves evidence coverage and final answers.

Prerequisites and starting inputs

Lab 1 harness; document corpus with stable IDs; relevance judgments.

Finish the final learning unit for Week 2, then run the starter fixtures. Preserve the preceding week's artifact and configuration.

Architecture

Warm-up diagnostic

The table contains illustrative fixture measurements, not live model benchmarks. All four candidates use the same 100 questions and corpus.

Choose a deployable candidate under the stated constraints: correctness ≥90%, citation precision ≥95%, p95 ≤2 seconds.

Diagnostic hint

Apply the hard requirements before optimizing cost.

Diagnostic reasoning

Hybrid B is the only fixture candidate satisfying all three constraints. On another measured workload the winner may differ.

This browser check validates the stated fixture rule, not completion of the implementation lab.

Guided implementation path

Starting artifact: the final unit of Week 2 and the preceding week's versioned experiment/state contracts. Download and run the engineering fixtures →

Use Python 3.10+ for the standard-library fixtures. Live model, framework, MCP and GPU experiments require separately pinned dependencies and declared hardware/provider access. Keep deterministic fixture results separate from real measurements.

CHECKPOINT 1 / 5 · WORKED START

Establish the input contract

Run python coursekit.py retrieval. Normalize source_id, revision, section/span, text and scope from a small QASPER development subset.

Expected intermediate result
Fixture Recall@2=0.5 and reciprocal rank=0.5; every real passage resolves to its source.
Stuck? Inspect this boundary

A nonempty passage can still be incorrectly extracted. Inspect tables and boundary examples.

CHECKPOINT 2 / 5 · GUIDED BUILD

Implement and inspect

Implement all eight chunking styles on the small development corpus; preserve offsets and inspect one boundary failure for each.

Expected intermediate result
A boundary audit and bounded chunking ablation, including overlap and parent expansion costs.
Stuck? Inspect this boundary

Deduplicate overlapping spans before reporting unique evidence recall.

CHECKPOINT 3 / 5 · GUIDED BUILD

Implement and inspect

Build BM25-only, vector-only, hybrid, hybrid+rereank, document-tree and long-context adapters returning the same evidence shape.

Expected intermediate result
Six configurations share corpus, scope, generator, output limit and declared context/call budgets.
Stuck? Inspect this boundary

Do not give long-context the gold document. Keep an oracle run in a separate diagnostic table.

CHECKPOINT 4 / 5 · INDEPENDENT TRANSFER

Implement and inspect

Add query transformations and context ledgers; record candidates before fusion, after fusion, after reranking and after budget selection.

Expected intermediate result
Each lost relevant item can be located at a specific boundary.
Stuck? Inspect this boundary

If no relevant evidence reaches the reranker, investigate candidate recall first.

CHECKPOINT 5 / 5 · INDEPENDENT TRANSFER

Produce the evidence

Run frozen queries; report Recall@5/10, MRR, NDCG, context precision, correctness, citations, latency, tokens, index bytes/build/update time and cost.

Expected intermediate result
Per-query results, paired comparisons, failure slices and a workload-specific architecture decision.
Stuck? Inspect this boundary

Keep missing evidence and parse failures in denominators. Similarity is not answer correctness.

Required experiments

Compare:

  1. BM25
  2. vector retrieval
  3. hybrid retrieval
  4. hybrid + reranker
  5. long-context / no-RAG baseline

Metrics:

  • Recall@5
  • Recall@10
  • MRR
  • NDCG
  • context precision
  • answer correctness
  • latency
  • token cost

Run all five canonical baselines. Sweep retrieval depth and rerank depth; change one factor at a time. Measure middle-position evidence and irrelevant distractors.

Required: BM25-only, vector-only, hybrid, hybrid plus reranking, document-tree navigation and long-context, with identical non-oracle source access and budgets.

Metrics and interpretation

Recall@5; Recall@10; MRR; NDCG; context precision; answer correctness; latency; token cost.

Preserve per-case outcomes, denominators, model/data/configuration revisions, run mode, paired comparisons and uncertainty. Separate deterministic fixtures from live measurements.

Failure cases

Identifier mismatch; stale evidence; lost provenance; long-context truncation; contradictory sources; absent answer.

Deliverables

Relevance labels, frozen corpus manifest, six required configurations, paired ablation tables, and a deployment recommendation.

Include every guided checkpoint, raw experiment results, failed cases, a decision memo and reproduction instructions.

Stretch goals

Add HyDE or multi-query retrieval and justify extra calls using the same held-out set.

Extra scale, frameworks and sweeps follow the required experiment; they do not replace it.
