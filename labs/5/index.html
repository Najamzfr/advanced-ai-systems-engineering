LAB 5 / WEEK 05

Red-Team the Agent

Build at least 50 attacks and measure the effectiveness of enforceable defenses.

Objective

Build at least 50 attacks and measure the effectiveness of enforceable defenses.

Prerequisites and starting inputs

Lab 3 runtime; MCP tools; isolated fixtures; no real secrets.

Finish the final learning unit for Week 5, then run the starter fixtures. Preserve the preceding week's artifact and configuration.

Architecture

Warm-up diagnostic

A reviewer approves draft A for a sandbox destination. The agent changes the text and destination but reuses the old approval token.

Select required checks immediately before dispatch.

Diagnostic hint

Approval must describe what will actually happen.

Diagnostic reasoning

Reject the changed action, require new approval, and validate identity, expiry, digest, and destination.

This browser check validates the stated fixture rule, not completion of the implementation lab.

Guided implementation path

Starting artifact: the final unit of Week 5 and the preceding week's versioned experiment/state contracts. Download and run the engineering fixtures →

Use Python 3.10+ for the standard-library fixtures. Live model, framework, MCP and GPU experiments require separately pinned dependencies and declared hardware/provider access. Keep deterministic fixture results separate from real measurements.

CHECKPOINT 1 / 5 · WORKED START

Establish the input contract

Map document, tool, memory, plan and API boundaries to attacker control and protected effects.

Expected intermediate result
Each threat case names entry point, asset, intended effect and enforcement point.
Stuck? Inspect this boundary

A generic "prompt injection" label does not specify what must be prevented.

CHECKPOINT 2 / 5 · GUIDED BUILD

Implement and inspect

Implement scoped tools, destination/path checks, secret isolation and approval digest validation.

Expected intermediate result
Denied-scope and changed-action fixtures fail before effects execute.
Stuck? Inspect this boundary

A prompt or roots list is not an OS/network/business permission boundary.

CHECKPOINT 3 / 5 · GUIDED BUILD

Implement and inspect

Create at least 50 attacks and benign controls, with held-out variants and outcome labels.

Expected intermediate result
Attack matrix includes attempted, claimed and executed effects separately.
Stuck? Inspect this boundary

Use sink/audit evidence to score effects; a model claiming "sent" is not proof of dispatch.

CHECKPOINT 4 / 5 · INDEPENDENT TRANSFER

Implement and inspect

Compare defenses on attack success, false refusal, benign task success, cost and latency.

Expected intermediate result
Paired report preserves the threat surface and limitations of the sample.
Stuck? Inspect this boundary

Zero observed successes does not establish universal security.

CHECKPOINT 5 / 5 · INDEPENDENT TRANSFER

Produce the evidence

Write one incident postmortem and seed Project 2 with real transactions plus synthetic consent policy.

Expected intermediate result
Timeline, root cause, regression repair, transaction validation and explicit synthetic fixtures.
Stuck? Inspect this boundary

Never infer contact/consent or campaign uplift from historical purchases.

Required experiments

Create:

≥50 attacks

Examples:

  • direct prompt injection
  • malicious webpage instruction
  • poisoned document
  • malicious tool argument
  • unauthorized destructive action
  • secret extraction
  • infinite loop attempt

Implement:

Input Validation
      +
Context Isolation
      +
Tool Permissions
      +
Least Privilege
      +
Output Validation
      +
Human Approval
      +
Audit Logging

Compare prompt-only controls with executable policy controls. Include adversarial tool output, poisoned memory, and approval substitution.

Metrics and interpretation

Attack success rate; benign task success; false rejection; unauthorized effects; escalation rate; recovery; overhead.

Preserve per-case outcomes, denominators, model/data/configuration revisions, run mode, paired comparisons and uncertainty. Separate deterministic fixtures from live measurements.

Failure cases

SSRF; unapproved destination; memory poisoning; approval for altered arguments; tool output interpreted as instruction.

Deliverables

Threat model, ≥50 attacks, benign controls, defense implementation, security report, and regression suite.

Include every guided checkpoint, raw experiment results, failed cases, a decision memo and reproduction instructions.

Stretch goals

Build a malicious MCP fixture server and measure client containment without exposing actual services.

Extra scale, frameworks and sweeps follow the required experiment; they do not replace it.
