LAB 5 / WEEK 05

Red-Team the Agent

Build at least 50 attacks and measure the effectiveness of enforceable defenses.

Objective

Build at least 50 attacks and measure the effectiveness of enforceable defenses.

Prerequisites

Lab 3 runtime; MCP tools; isolated fixtures; no real secrets.

Review Week 05 →

Architecture

Canonical lab brief

Create:

≥50 attacks

Examples:

  • direct prompt injection
  • malicious webpage instruction
  • poisoned document
  • malicious tool argument
  • unauthorized destructive action
  • secret extraction
  • infinite loop attempt

Implement:

Input Validation
      +
Context Isolation
      +
Tool Permissions
      +
Least Privilege
      +
Output Validation
      +
Human Approval
      +
Audit Logging

Implementation steps

  1. Step 01

    Define assets, attackers, trust boundaries, tool permissions, and allowed data destinations.

  2. Step 02

    Create at least 50 versioned cases across direct/indirect injection, poisoning, malicious arguments, exfiltration, excessive agency, and loops.

  3. Step 03

    Implement policy enforcement before tool execution, output validation, least privilege, context isolation, and human approval.

  4. Step 04

    Run attacks and benign controls before and after defenses. Preserve per-case intended behavior and observed outcome.

  5. Step 05

    Inspect bypasses and false positives. Add regression cases for every fix and redact sensitive trace content.

Experiment requirements

Compare prompt-only controls with executable policy controls. Include adversarial tool output, poisoned memory, and approval substitution.

Record dataset and code revisions, seeds, configuration, hardware, and per-case outcomes. Freeze test data before selecting the winning configuration. Report missing or blocked runs honestly.

Metrics

Attack success rate; benign task success; false rejection; unauthorized effects; escalation rate; recovery; overhead.

Publish denominators and per-slice results. Use paired comparisons and uncertainty estimates where outcomes are stochastic.

Failure cases

SSRF; unapproved destination; memory poisoning; approval for altered arguments; tool output interpreted as instruction.

Deliverables

Threat model, ≥50 attacks, benign controls, defense implementation, security report, and regression suite.

Stretch goals

Build a malicious MCP fixture server and measure client containment without exposing actual services.
