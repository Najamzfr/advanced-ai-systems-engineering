WEEK 01 / WEEKLY BUILD

Model evaluation harness

One working system, measured against a fixed data pack. Estimated effort: 20–25 hours.

BUILD THE SYSTEM

A support team needs a defensible way to compare models before choosing one for customer queries.

Deliverable. A CLI that evaluates two model configurations on 300 stratified cases and produces a model-selection report.

DataBANKING77 starter sliceToolsProvider adapter, pytest, structured outputs, calibrated judgeSourcePolyAI/BANKING77 · CC BY 4.0

Start here

  1. Download the runnable starter

    Unzip it, then run make setup. Python and PowerShell equivalents are documented in the README.

  2. Run the smoke example

    Run make run. Read the denominators before interpreting any score.

  3. Fetch the assigned data

    Run the data script and verify the generated manifest before making a benchmark claim.

Worked example

  1. Inspect the contract

    Open evals/providers.py and trace one text through both deterministic providers.

    Expected: both providers return a label, a schema flag and a latency measurement.

  2. Read the report

    Open reports/metrics.json after make run. Compare the denominators before reading any score.

    Expected: dataset: smoke_fixture, cases: 3 for each model, and judge_denominator: 0.

  3. Run the real benchmark

    Fetch the approved data, run make evaluate, add 30 human audit rows, then run make grade.

    Expected: the grader passes only with real data, 300+ paired cases and 30+ audit rows.

Do not promote the smoke run.A perfect score on three hand-picked cases is a wiring check, not evidence that one model is better.

Checkpoint 1 walkthrough

Start from a clean unzip. Run make setup; confirm the contract message. Run make run; open reports/metrics.json and verify that both baseline-v1 and robust-v2 have the same case denominator. Run make check-step-1. It should print one PASS line and name the exact missing file or key if you skipped a command. Only after this wiring check should you fetch BANKING77.

Checkpoint 1 exit condition. make check-step-1 returns PASS and points to reports/metrics.json.
