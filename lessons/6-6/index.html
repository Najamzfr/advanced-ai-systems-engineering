Static batching waits for a group and can waste capacity when short requests finish early. Continuous batching admits or removes sequences at iteration boundaries, subject to memory and scheduling constraints. Higher concurrency can raise throughput until queues and cache pressure harm tail latency. Prefix caching, quantization, speculative decoding, and model routing address different bottlenecks.

Speculative decoding uses a draft model to propose tokens and a target model to verify them; gains depend on acceptance rate and verification overhead. Quantization can reduce weight memory/bandwidth but may change quality or kernel support. Choose one optimization, freeze workload and model-quality tests, warm up separately, and measure steady state plus overload. GPU utilization alone does not establish useful throughput or acceptable latency.

Topics:

TTFT
Time to first token includes waiting, prompt processing and the start of generation.
Tokens/sec
State whether token rate is measured per request or across the server, and under which workload.
Throughput
Count completed work per unit time while checking that latency and quality constraints still hold.
Concurrency
Measure the number of requests in flight, including queued work when that is part of the definition.
Batching
Execute multiple requests together to use hardware efficiently, with latency costs measured explicitly.
Continuous batching
Admit new requests as others finish instead of waiting for the entire batch to complete.
KV cache
Reuse attention keys and values for earlier tokens during decoding, at a memory cost that grows with retained tokens.
Prefix caching
Reuse computation for matching prompt prefixes while respecting model revision and isolation requirements.
Quantization
Reduce numeric precision to save memory or computation, then measure quality on the intended workload.
Speculative decoding
A cheaper draft proposes tokens that the target model verifies; speed depends on acceptance and workload.
Model routing
Choose a model using task needs and measured constraints, with explicit escalation conditions.
GPU utilization
Measure device activity alongside useful throughput because a busy GPU does not prove efficient task completion.

Work through an example

A batch contains A with two tokens left and B with ten. After A finishes, continuous batching can admit C instead of waiting for B. If C has a very long prompt, its prefill can still interfere with decode unless scheduling handles that trade-off.

Inspect scheduling trade-offs

Read batching and decoding optimization. Explain how a long prefill can delay requests already decoding.

Exercise

Apply the explanation

Concurrency doubles throughput but p95 rises from 1.5 to 6 seconds. Is the optimization successful for a two-second SLO?

Read the explanation

Not under that SLO. Plot throughput versus latency and choose an admission/concurrency point meeting the constraint, or add capacity/change workload assumptions. Report overload errors as well.

Cheat sheet

Continuous batching and serving optimization

Definition

An inference service admits requests, schedules model execution and returns generated tokens.

Intuition

Queueing, prefill and decoding contribute different parts of latency.

Formula

TTFT=tfirst token−tarrival\mathrm{TTFT}=t_{\mathrm{first\ token}}-t_{\mathrm{arrival}}

Use a declared request boundary. Queueing and prompt prefill contribute to time to first token.

Common mistake

Tokens per second alone does not establish the user's response-time target.

Production notes

Measure TTFT, completion latency, throughput, errors and memory under stated load.
