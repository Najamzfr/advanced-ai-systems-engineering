The planner defines work; executors gather evidence; the verifier evaluates support. Keep these contracts narrow. A verifier should return SUPPORTED, PARTIAL, CONTRADICTED, or INSUFFICIENT with source references and a reason. The writer consumes verdicts and does not upgrade them. A second model is not automatically independent: shared context and model biases can correlate mistakes.

Represent claims and supports/contradicts edges explicitly. Preserve negative evidence and unresolved contradictions. Verify citation existence, location, and entailment separately. Evaluate unsupported-claim rate and citation completeness alongside report usefulness. More verification calls can increase latency without improving detection, so compare with a single-agent baseline using the same questions and budget.

Work through an example

A source states a technique works on synthetic data; another reports failure on real data. The verifier marks a universal-success claim CONTRADICTED and records both references. The writer should describe the scope difference, not average the two claims into vague confidence.

Exercise

Apply the explanation

A verifier returns SUPPORTED but cites only the writer's own summary. Is the verification independent enough?

Read the explanation

No. Require original source spans and check the claim against them. A summary can guide navigation but cannot replace source evidence; blind the verifier to persuasive rationale when practical.

Cheat sheet

Planner, executor, verifier contracts

Definition

A planner defines bounded work; executors perform steps and return evidence for review.

Intuition

Dependencies and acceptance conditions make a plan executable.

Pattern

Create a claim ledger with verdicts and source spans, then compare writer output against ledger status.

Common mistake

Parallel execution is invalid when a step depends on unfinished evidence.

Production notes

Persist plan revisions, step state, evidence references and retry limits.
