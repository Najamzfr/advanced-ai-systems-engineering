An inverted index maps terms to postings. BM25 rewards term matches using inverse document frequency and saturating term frequency with length normalization; it works well for rare identifiers but misses paraphrases. Dense retrieval embeds queries and passages into a shared space, then ranks by a chosen distance. Cosine compares direction; dot product also reflects magnitude unless vectors are normalized. Model and normalization must match across indexing and queries.

Exact vector search scans the corpus. Approximate nearest-neighbor methods trade recall for speed. HNSW navigates a layered neighbor graph; construction/search breadth and connectivity affect memory, latency, and recall. ANN recall compares approximate neighbors against exact neighbors, while evidence recall compares retrieved evidence against human relevance labels. A perfect ANN result can still retrieve semantically wrong evidence.

Work through an example

For query "ERR_403B after v2.7," BM25 can preserve the rare code while a semantic index retrieves generic authentication advice. A paraphrase "why can I no longer sign in?" may favor dense search. Both errors justify complementary candidate sources, not a universal winner.

Cheat sheet

Lexical, dense, and approximate search

Definition

A retriever selects source evidence for a generator to use when answering.

Intuition

The generator cannot cite evidence that retrieval never supplied.

Pattern

Implement BM25-only and vector-only runs. Save exact-versus-ANN diagnostics independently of answer evaluation.

Common mistake

Semantic similarity does not establish the validity or freshness of a source.

Production notes

Preserve source revision, access scope, passage IDs and exact evidence spans.
