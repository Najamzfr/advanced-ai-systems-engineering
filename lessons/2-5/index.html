Query expansion adds aliases or terms; multi-query retrieval asks several equivalent questions and merges candidates. HyDE generates a hypothetical answer, embeds it, and searches for actual documents nearby. The hypothetical text is a search aid, never a source. Contextual retrieval attaches a document-aware explanation to a chunk before indexing; keep that generated context separate from original evidence and validate its effect.

Multi-hop questions require an intermediate result: find an entity, then retrieve its relation or comparison. Represent each hop as a subquestion with required evidence and a stop rule. Error compounds when an early unsupported entity drives later queries. Bound query count, deduplicate results, preserve provenance, and compare against the untransformed query under equal token/call budgets.

Work through an example

Question: "Which later study contradicted the method evaluated in P17?" First identify the method in P17, then search for later studies and inspect contradiction evidence. A generated method name from HyDE is not sufficient to anchor the second hop.

Evaluate query expansion

Compare retrieval strategies. Track whether extra queries recover needed evidence or only increase redundancy and cost.

Synthetic query aid was mixed into the evidence store. Label it as non-citable and permit citations only to retrieved source spans. Re-evaluate grounding separately from recall.

Cheat sheet

Query expansion and multi-hop retrieval

Definition

A retriever selects source evidence for a generator to use when answering.

Intuition

The generator cannot cite evidence that retrieval never supplied.

Pattern

Add transformation_type, generated_query, hop_id, call_budget, and evidence_refs to each retrieval trace.

Common mistake

Semantic similarity does not establish the validity or freshness of a source.

Production notes

Preserve source revision, access scope, passage IDs and exact evidence spans.
