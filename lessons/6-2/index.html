Training data is an engineered artifact with a schema, provenance, label policy, and version. Inspect coverage by task, difficulty, language, failure category, and output form. Quantity cannot compensate for systematically wrong or repetitive labels. Deduplicate exact and near-duplicate examples before splitting by source/entity/time. Hold out evaluation data before generating variants.

Annotation needs instructions, examples, adjudication, and disagreement tracking. Synthetic data and distillation can cheaply expand coverage but inherit the teacher's mistakes and style. Filter against explicit quality criteria, audit a sample, and preserve whether an example is observed, human-authored, or generated. Avoid training on test prompts, answers, or near-duplicates. Build a general-capability retention set to detect catastrophic forgetting.

Reading

AI Engineering Chapter 8:

Data quality
Check labels, source validity and task relevance before increasing the training set size.
Coverage
Include the important task and failure slices rather than relying on the total example count.
Quantity
Count independent useful examples as well as generated rows so duplication does not inflate apparent data size.
Annotation
Define label rules, reviewer guidance and adjudication for disputed examples.
Synthetic data
Generate examples with recorded provenance and verify them before they enter training or evaluation.
Distillation
Train a smaller model from a teacher's outputs while checking for copied teacher errors.
Deduplication
Remove duplicates and near duplicates before splitting to prevent leakage across datasets.
Filtering
Apply documented acceptance rules and measure which task slices they remove.
Cleaning
Correct malformed records and inconsistent fields without silently changing the intended labels.

Work through an example

Generating ten paraphrases of each of 100 examples and then randomly splitting creates nearly identical training/test pairs. Split the original examples first, then generate within the training partition. Report source-level counts as well as expanded row counts.

Cheat sheet

Dataset engineering for adaptation

Definition

Adaptation changes model behavior through training; retrieval supplies evidence at request time.

Intuition

Diagnose a knowledge problem separately from a behavior or serving problem.

Formula

ΔW=BA,Nadapter=r(din+dout)\Delta W=BA,\qquad N_{\mathrm{adapter}}=r(d_{\mathrm{in}}+d_{\mathrm{out}})

For a LoRA update, B and A have rank r. This count excludes biases and any other trainable parameters.

Common mistake

Training on poor or leaked examples can raise a score without improving the system.

Production notes

Track dataset lineage, splits, retention tests and adapter/model compatibility.
