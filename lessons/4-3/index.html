Compare six arrangements: sequential handoff, parallel specialists, a central supervisor, hierarchical teams, peer collaboration/debate, and a shared blackboard. Sequential handoff simplifies ordering but can amplify early errors. Parallel specialists reduce independent-work latency but need a merge policy. A supervisor centralizes routing and termination; hierarchy delegates scope at the cost of additional coordination. Peer collaboration supports critique but risks circular agreement. A blackboard shares structured state and needs ownership/version rules.

Define who owns the task, who can write each field, what context crosses boundaries, and who ends the process. An agent used as a tool should expose a typed request/result contract and inherit only necessary permissions. More role labels do not create independent expertise. Keep calculations deterministic and use specialists only when an evaluation demonstrates added value.

Multi-agent coordination

Architecture comparisons

Router and specialist
A router chooses one specialist for a task; test routing errors separately from specialist accuracy.
Supervisor and workers
A supervisor allocates work and budgets while workers return bounded outputs.
Planner and executors
A planner declares dependencies; executors complete tasks under explicit tool contracts.
Agent as a tool
A calling agent delegates through a bounded interface with input, output and budget limits.
Parallel agents and synthesizer
Independent workers collect results concurrently; a synthesizer resolves overlap and conflict.
Researcher, critic and writer
Research supplies evidence, critique checks claims, and writing preserves any unresolved limitations.

Work through an example

A document researcher and a quantitative worker run in parallel. Their outputs are merged by evidence ID; only the quantitative worker's tested calculator supplies numbers. A supervisor owns budget and completion. This is a concrete topology; "a team of experts collaborates" is not.

Inspect agent responsibilities

Read conversable agents and conversation programming. Identify the owner of state, termination and the global budget.

Exercise

Apply the explanation

Workers can all overwrite a shared final_answer field. Which architecture failure is likely, and how would you repair it?

Read the explanation

Race conditions and lost/contradictory state. Assign field ownership, immutable evidence records, versioned merges, and a single finalization authority. A blackboard needs concurrency rules.

Cheat sheet

Six multi-agent arrangements

Definition

A multi-agent system divides work among model-driven components with explicit handoffs.

Intuition

Coordination is another source of latency and failure.

Pattern

Draw all six arrangements, then implement only the three required comparison architectures.

Common mistake

More agents can amplify the same error instead of providing independent verification.

Production notes

Give each role a contract, owner, budget and observable failure path.
