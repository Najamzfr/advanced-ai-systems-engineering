ReAct alternates action selection with environment observations. The useful engineering record is the decision, tool arguments, observation, evidence, and changed state; a generated rationale is not proof. Represent decisions as a tagged union: tool_call, final, or escalate. Validate before execution and append a structured result with success, error, and evidence references.

The runtime owns maximum steps, deadline, token/cost budget, repeated-action detection, and completion criteria. Terminate when evidence is sufficient, no safe action remains, or a budget expires. Preserve an incomplete status instead of fabricating a conclusion. Separate recoverable errors from policy denials. A denial should not become a prompt to try alternate encodings of the forbidden action.

Cheat sheet

Build a bounded ReAct loop

Definition

A ReAct loop alternates a model's proposed action with an observed tool result.

Intuition

The runtime validates and executes actions; the model only proposes them.

Pattern

Implement the scratch loop first with a scripted model adapter; save every state transition before using one framework.

Common mistake

Unbounded retries or treating a proposed action as permission creates unsafe behavior.

Production notes

Enforce tool budgets, deadlines, stop reasons and durable action identifiers.
