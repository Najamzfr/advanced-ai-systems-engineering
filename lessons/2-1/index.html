Retrieval starts with trustworthy addressing, not embeddings. Parse source_id, revision, document title, section path, paragraph/page offsets, timestamp, and access scope. Keep raw content separate from normalized text. Record parser version and content hash so an index can be reproduced and invalidated. Detect empty extraction, repeated headers, tables, and OCR failures instead of embedding garbage.

Deduplicate equivalent content without discarding legitimate revisions. A tombstone or permission change must propagate to every index and cache. For QASPER, section and paragraph structure supplies evidence addresses; PDF and webpage adapters should produce the same interface. Split evaluation by source before deriving chunks. Otherwise near-identical paragraphs leak into development and held-out sets.

Advanced retrieval architecture

Work through an example

Paper P17 revision r2 has section Methods paragraph 4. Store P17:r2:methods:p4 as an evidence address and keep its normalized text plus raw-source locator. A later r3 paragraph with changed results is a new evidence version. An answer citing r2 must not silently display r3.

Read the explanation

No. Enforce scope before retrieval or before any candidate leaves the trusted data boundary, and invalidate stale caches/index records. Prompt instructions are not access control.

Cheat sheet

Ingest evidence with provenance

Definition

A retriever selects source evidence for a generator to use when answering.

Intuition

The generator cannot cite evidence that retrieval never supplied.

Pattern

Produce sources.jsonl, a manifest, rejected-extraction records, and a source-disjoint question split.

Common mistake

Semantic similarity does not establish the validity or freshness of a source.

Production notes

Preserve source revision, access scope, passage IDs and exact evidence spans.
