A workflow encodes allowed transitions in application code; an agent lets a model select actions based on observations. A workflow can contain many LLM calls and still be a workflow. Start with chaining for known dependent steps, routing for known task classes, and parallelization for independent work. Add evaluator, optimizer loops only when feedback can improve a candidate and termination is explicit.

An agent earns its complexity when the required sequence depends on information discovered during execution. Its environment includes tools, observations, state, and a success criterion. The model proposes; the runtime enforces allowed actions and resource limits. Tool use alone does not require an unconstrained loop. Compare the same workload under a fixed workflow and an agent before adopting dynamic control.

Workflow vs agent

Agent model

Observation
An agent receives a tool result or environment update that informs its next decision.
State
Record the facts, progress and pending actions needed to continue a task.
Policy
A decision rule selects the next action from the available state and observations.
Action
A proposed operation changes state or requests information and must pass the application's checks.
Environment
The external system supplies observations and determines the real effects of actions.
Tool
A callable interface exposes a bounded operation with defined inputs, outputs and permissions.
Termination
Stop when the task succeeds, evidence is insufficient, a hard failure occurs or the budget is exhausted.
Budget
Set enforceable limits on calls, tokens, elapsed time and external effects.
Recovery
Resume or end a failed operation according to its recorded state and whether its effect is known.

Work through an example

A receipt extraction task always parses, validates totals, and stores a record. A workflow handles it. Researching conflicting claims may require discovering a new source and revising the search plan; a bounded agent can help. Both need deterministic schema and permission checks.

Cheat sheet

Who controls the next step?

Definition

A workflow follows authored transitions; an agent can choose the next action within runtime limits.

Intuition

Use fixed control flow when the task's branches are known.

Pattern

Write transition diagrams for both designs, then choose a baseline for the research system.

Common mistake

Adding model autonomy does not make an otherwise fixed pipeline more reliable.

Production notes

Keep policy checks outside the model and expose the actual control flow in traces.
