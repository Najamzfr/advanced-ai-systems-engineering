Chunking selects the unit of retrieval and citation. Fixed token windows are easy to reproduce but can cut a definition from its condition. Overlapping windows reduce boundary loss while increasing duplicate candidates and storage. Sentence windows preserve syntax; paragraph chunks preserve local argument; recursive splitting uses progressively smaller separators. Semantic boundaries group related passages but depend on an additional model or heuristic. Document-structure chunks follow headings, tables, and sections. Hierarchical parent, child retrieval indexes a precise child and expands to its containing context.

Keep eight strategies visible: fixed, overlap, sentence, paragraph, recursive, semantic, structure-aware, and parent, child. Compare on a small development grid; do not combine every size and retriever into an unbounded sweep. Maintain exact source offsets and deduplicate overlap before calculating context precision. A chunk containing half of a table may be unusable even when its embedding is relevant.

Context engineering

Bevidence=W−Boutput−Bpolicy−Btask−BmemoryB_{\mathrm{evidence}}=W-B_{\mathrm{output}}-B_{\mathrm{policy}}-B_{\mathrm{task}}-B_{\mathrm{memory}}

Reserve output and required instructions before allocating evidence. A negative remainder means that the context plan is infeasible.

Evidence boundaries

Fixed length
Use a fixed token count as a baseline, then check whether the split cuts through necessary evidence.
Sentence
Split at sentence boundaries to preserve local meaning, then test whether evidence spans multiple sentences.
Recursive
Split using progressively smaller separators until chunks fit the size limit.
Semantic
Group nearby text by meaning, then test boundary quality and the added indexing cost.
Structural
Use headings, tables and document sections as boundaries so chunks retain their document role.
Parent-child
Retrieve a small child chunk and return its larger parent when the answer needs surrounding context.
Proposition-level
Index individual factual statements while keeping links to the original passage for verification.
Hierarchical
Store multiple levels of document detail so retrieval can navigate from summaries to evidence.

The important question is:

How do we prove that a chunking strategy improved system performance?

Work through an example

A 120-token paragraph says "this improvement applies only to synthetic data." A fixed cut retains the improvement and drops the qualifier. Parent expansion restores the condition, but consumes more context. The right test checks claim support and total context tokens, not only retrieval similarity.

Read the explanation

Deduplicate evidence IDs or spans, measure unique evidence recall and context precision, then compare the same token budget. Limit redundant candidates or expand one canonical parent instead of retaining every overlap.

Cheat sheet

Eight chunking strategies and evidence boundaries

Definition

Context engineering chooses the instructions, evidence, state and tools supplied to a model.

Intuition

The context window is a limited working space, not a permanent database.

Formula

Bevidence=W−Boutput−Bpolicy−Btask−BmemoryB_{\mathrm{evidence}}=W-B_{\mathrm{output}}-B_{\mathrm{policy}}-B_{\mathrm{task}}-B_{\mathrm{memory}}

Reserve output and required instructions before allocating evidence. A negative remainder means that the context plan is infeasible.

Common mistake

Filling the window can crowd out useful evidence or exceed the output reserve.

Production notes

Version context assembly, enforce access rules and record truncation decisions.
