An incident timeline starts with the earliest relevant input and follows policy decisions, tool calls, state changes, and effects. Record what was observed, what is inferred, and what remains unknown. Identify the failed boundary and contributing conditions rather than blaming "the model hallucinated." Redact secrets and unnecessary personal data while preserving IDs needed for correlation.

Contain the effect, repair the boundary, and add a regression test at the smallest responsible component plus an end-to-end case. Verify benign behavior after the fix. Assign an owner, acceptance check, rollback trigger, and monitoring signal. Avoid treating a prompt patch as proof that the underlying capability misuse is impossible.

Cheat sheet

Incident analysis and regression repair

Definition

Observability connects logs, metrics and traces to the system's requests and decisions.

Intuition

A trace should explain where time, cost and failure entered a request.

Pattern

Submit one postmortem with timeline, root cause, containment, repair, regression, and residual risks.

Common mistake

A missing parent-child link can make queueing or worker delays invisible.

Production notes

Record span links, revisions and policy outcomes while redacting secrets.
