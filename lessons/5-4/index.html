Build at least 50 attack cases distributed across the boundaries in your threat model. Record attacker control, payload, intended forbidden effect, expected policy result, actual tool trace, and outcome. Keep harmless task failures separate from successful unauthorized effects. Include encoding, role impersonation, multi-turn persistence, malicious tool output, and evidence poisoning where applicable.

Use a fixed attack set for paired defense comparison and a held-out set for final claims. Measure attack success rate, benign task success, false refusals, latency, and cost. A defense that blocks all tasks is secure only in a trivial sense and may be unusable. Do not call zero observed attacks a proof of universal safety; report the tested threat surface and sample size.

Work through an example

A defense reduces successful forbidden actions from 12/50 to 1/50 but raises false refusal from 2/100 to 18/100 benign cases. Both changes belong in the release decision; the remaining attack requires a boundary-specific repair.

Measure defense trade-offs

Compare defenses using both attack success and benign-task refusal. Define the denominator for each measurement.

Cheat sheet

Run a reproducible red-team matrix

Definition

A trust boundary separates data the system may inspect from instructions it is authorized to execute.

Intuition

Retrieved documents and tool output remain untrusted data.

Formula

ASR=Nattacks achieving the forbidden objectiveNattempted attacks\mathrm{ASR}=\frac{N_{\mathrm{attacks\ achieving\ the\ forbidden\ objective}}}{N_{\mathrm{attempted\ attacks}}}

Define the forbidden effect before testing. Report benign task success separately from attack success rate.

Common mistake

A safe final answer does not cancel an unauthorized tool effect.

Production notes

Enforce least privilege, human approval and output checks at execution time.
