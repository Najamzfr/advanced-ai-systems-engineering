A tool contract includes types, units, allowed ranges, identity/scope, error codes, timeout, and side-effect semantics. Validate model arguments against both schema and domain invariants. A syntactically valid customer ID can still be outside the caller's scope. Deterministic calculations belong inside tested functions, not model arithmetic.

A transport timeout does not prove an effect failed. The server may have committed a write before the reply was lost. Assign a stable idempotency key to the logical operation, persist its status, and query by that key before retrying. Retry transient failures with a bounded backoff and deadline; do not retry authorization denials. If the external service cannot deduplicate or expose status, preserve UNKNOWN and require reconciliation rather than promising exactly-once execution.

Tool execution and unknown outcomes

Tool inputs and effects

tool schemas

Typed arguments
Validate tool inputs against explicit types, ranges and allowed identifiers before execution.
Idempotency
Repeating the same logical request with the same key must not create an extra logical effect.
Retries
Repeat transiently failed work within limits after checking whether the earlier attempt may have succeeded.
Timeouts
Bound waiting time; a timeout does not prove that an external operation failed to take effect.
Side effects
Writes, sends and other external changes require stronger controls than read-only operations.
Transaction boundaries
Specify which state changes commit atomically and how work outside that transaction is reconciled.
Least privilege
Grant only the operations and data scope needed for the current task.
Reversible operations
Define and test the operation that restores the prior state when reversal is possible.
Irreversible operations
Require authorization and effect reconciliation before actions that cannot reliably be undone.

Work through an example

A save_evidence request with key run17:claim4 succeeds, but the response disappears. The retry uses the same key and receives the existing evidence ID. Generating a new key per HTTP attempt would create two effects.

Cheat sheet

Tool contracts, effects, and unknown outcomes

Definition

A tool contract defines accepted inputs, permissions, outputs, effects and errors.

Intuition

An attempted operation and a confirmed effect are different states.

Pattern

Add typed contracts, denied-scope fixtures, malformed results, and crash-after-effect tests to Lab 3A.

Common mistake

A timeout does not prove that an external write failed.

Production notes

Use stable action IDs, reconciliation and structured error categories.
