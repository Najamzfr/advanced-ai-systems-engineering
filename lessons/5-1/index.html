End-to-end task success is necessary but insufficient for debugging. Add tool selection accuracy, argument correctness, policy compliance, evidence coverage, step efficiency, recovery success, and termination behavior. A trajectory is a sequence of states, actions, and observations. Compare it with required invariants, not one exact ideal path when several paths are valid.

Distinguish failures caused by planning, retrieval, tool semantics, model synthesis, authorization, and infrastructure. Preserve primary and secondary causes with timestamps and evidence. Evaluate on normal, edge, and adversarial cases; report per-slice denominators. A successful final answer does not excuse an unauthorized intermediate action.

Agent Evaluation

Evaluate separately:

Request and intent
Check the authenticated request, intended outcome and permitted scope before planning work.
Retrieval and planning
Check evidence relevance and whether planned tasks are necessary and allowed.
Tool selection and arguments
Validate the operation, identifiers, value ranges and permissions before execution.
Execution and trajectory
Record actual effects, retries and recovery, including actions omitted from the final answer.
Final answer
Evaluate correctness, evidence support and task completion without hiding earlier boundary failures.

Metrics:

Task success
Count tasks that satisfy the complete outcome contract, including permission and evidence requirements.
Tool accuracy
Check whether the selected tool was appropriate for the intended operation.
Argument correctness
Check that tool arguments refer to the right entities, values and authorization scope.
Trajectory efficiency
Compare useful completed work with the calls, tokens and elapsed time used to obtain it.
Unnecessary actions
Identify calls that add no required evidence or effect and can be removed without harming success.
Retry rate
Report how often operations repeat, with the denominator and failure classes.
Recovery rate
Measure how many injected or observed failures reach a valid recovered state.
Human escalation
Route unresolved or sensitive cases to a person with the evidence needed to decide.

Work through an example

A run answers correctly after fetching a disallowed customer profile. Its answer metric passes, but authorization compliance fails and the release must be blocked. Trajectory-level checks expose what the final text hides.

Not necessarily. Check dependency validity, cost, latency, and redundant work. Do not enforce an exact sequence unless the business process requires it.

Cheat sheet

Evaluate trajectories and components

Definition

An evaluation compares versioned outputs with a task-specific definition of success.

Intuition

Measure the component that could cause the observed failure.

Formula

Recall@K⁡=∣relevant∩top K∣∣relevant∣\operatorname{Recall@K}=\frac{|\mathrm{relevant}\cap\mathrm{top}\ K|}{|\mathrm{relevant}|}

Declare the relevant set, retrieval unit and query denominator. Candidate recall is not answer accuracy.

Common mistake

A higher aggregate score can hide a regression on a critical slice.

Production notes

Freeze case IDs and report denominators, uncertainty and failed runs.
