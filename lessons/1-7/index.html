Define stable case IDs and immutable run IDs. Each run records dataset hash, model and prompt versions, decoding configuration, evaluator version, timestamps, and run mode. Keep development decisions out of the final held-out report. A deterministic replay fixture checks the harness without pretending to benchmark an actual model.

For Project 1, normalize a source reference as source_id, revision, section_id, and exact span. A claim links to evidence references and an explicit support verdict. Implement the evaluation harness around this schema now: later retrieval and agent stages must return the same shape. Begin basic observability with a run ID and per-stage durations. Package a command that loads fixtures, evaluates them, and writes JSONL plus a summary. Week 7 adds distributed durability; reproducible files and explicit service contracts already matter here.

Work through an example

A replay run has model_revision="fixture-v1" and run_mode="replay". A real inference run has a provider/local model revision and measured token counts. Keep their summary tables separate so a deterministic smoke test cannot inflate your model results.

Cheat sheet

Package the evaluation contract

Definition

An evaluation compares versioned outputs with a task-specific definition of success.

Intuition

Measure the component that could cause the observed failure.

Formula

Recall@K⁡=∣relevant∩top K∣∣relevant∣\operatorname{Recall@K}=\frac{|\mathrm{relevant}\cap\mathrm{top}\ K|}{|\mathrm{relevant}|}

Declare the relevant set, retrieval unit and query denominator. Candidate recall is not answer accuracy.

Common mistake

A higher aggregate score can hide a regression on a critical slice.

Production notes

Freeze case IDs and report denominators, uncertainty and failed runs.
