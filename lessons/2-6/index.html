Context engineering chooses what enters the model's working set: stable instructions, current task, retrieved evidence, tool schemas, observations, and memory. Reserve output and tool overhead first. Select evidence by relevance, diversity, and support requirements; preserve contradictions rather than compressing them into false consensus. Reordering can change performance, so test evidence position explicitly.

Memory is state with a lifecycle. Short-term state tracks the current task; episodic records summarize past interactions; semantic memory stores durable facts; procedural memory stores reusable procedures. Each needs provenance, scope, expiry, and correction. Summaries are lossy derived data. Never promote a user document or tool response into trusted policy because it was summarized. Long-term memory retrieval must obey the same authorization boundary as the source.

Context requirements

context budgeting

Prompt organization
Separate instructions, task data and evidence with explicit roles and source labels.
Dynamic context
Select the evidence and state needed for the current step instead of resending every available item.
Context compression
Shorten context while checking that contradictions, identifiers and necessary details survive.
Long context vs RAG
Compare supplying the document set directly with retrieving selected evidence under matched task conditions.
Semantic memory
Store reusable facts with provenance and update rules rather than treating generated statements as verified facts.
Episodic memory
Store past events or interactions with timestamps so later tasks can recover what happened.
Procedural memory
Store reusable methods or instructions, with controlled updates because they influence future actions.
Working memory
Keep the temporary state needed for the current task within a bounded context budget.
Persistent memory
Retain state across sessions with access controls, retention limits and a way to correct it.
Memory poisoning
Untrusted content enters stored memory and later influences decisions as if it were trusted.
Provenance
Retain the source, revision and transformation history needed to trace a claim back to evidence.

Work through an example

An 8,192-token window reserves 1,200 for output, 1,000 for instructions/tools, 500 for the task, and 1,000 for relevant memory. Evidence gets at most 4,492 tokens. If an 800-token contradiction is omitted to preserve redundant support, the budget fits but the answer can still be wrong.

Cheat sheet

Context as a budgeted working set

Definition

Context engineering chooses the instructions, evidence, state and tools supplied to a model.

Intuition

The context window is a limited working space, not a permanent database.

Formula

Bevidence=W−Boutput−Bpolicy−Btask−BmemoryB_{\mathrm{evidence}}=W-B_{\mathrm{output}}-B_{\mathrm{policy}}-B_{\mathrm{task}}-B_{\mathrm{memory}}

Reserve output and required instructions before allocating evidence. A negative remainder means that the context plan is infeasible.

Common mistake

Filling the window can crowd out useful evidence or exceed the output reserve.

Production notes

Version context assembly, enforce access rules and record truncation decisions.
