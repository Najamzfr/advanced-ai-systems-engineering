An SLI is a measured indicator; an SLO is its target over a defined window; an SLA is an external agreement with consequences. Define task success, latency, and policy compliance at the user boundary. State the denominator and treatment of timeouts, cancellations, and invalid requests. A success-rate SLO and an absolute prohibition on unauthorized actions serve different purposes.

Release a candidate only after deterministic, evaluation, security, and performance gates. A canary exposes a small controlled fraction of representative traffic or replay load, with enough volume to interpret results. Compare by workload and policy scope; roll back on defined degradation. Version prompts, models, schemas, indexes, and policies together. A code rollback that leaves an incompatible index or database migration is incomplete.

Work through an example

For 10,000 eligible tasks and a 99% success SLO, the window allows 100 failures. If 80 have already failed, only 20 remain in the error budget. This budget does not authorize 20 security violations; those remain separate hard failures.

Cheat sheet

SLIs, SLOs, canaries, and rollback

Definition

Production architecture defines data, execution, policy and recovery boundaries.

Intuition

A deployed model is one component of a service with operational constraints.

Pattern

Create release gates, canary criteria, rollback command, and a compatibility plan for state and indexes.

Common mistake

A successful demo does not establish capacity or recovery behavior.

Production notes

Keep release gates, SLOs, canaries, rollback and incident evidence.
