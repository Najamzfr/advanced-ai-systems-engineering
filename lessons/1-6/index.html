Cost, tail latency, and model selection

Model selection is a constrained decision. First enforce minimum quality, privacy, tool reliability, and latency on each critical slice. Then compare feasible options using total cost per successful task, not headline price per token. Include input/output tokens, retries, retrieval, evaluation, and serving overhead. Cache hit rate must be measured with valid user, policy, and data scope.

Mean latency hides slow requests. Measure end-to-end p50/p95, time to first token, output length, and timeout rate under a declared arrival pattern. A fallback introduces another latency and error distribution; it is not free reliability. Route using observable task features or a separately evaluated classifier, then evaluate the complete routing policy on held-out tasks. A provider revision can change behavior without changing your prompt: maintain canaries and regression baselines.

Compare cost under the same success criteria. A cheaper request can be more expensive per successful task.

Work through an example

Illustrative rates: $0.20 per million input tokens and $0.80 per million output tokens; 2,000 input and 400 output tokens cost $0.00072/request. At 500,000 requests that is $360 model cost before retries, indexing, hosting, or review. A 10% full retry rate raises this component to $396. These are teaching rates, not current provider prices.

Choose a routing threshold

Read model routing and caching. Specify the quality and latency conditions under which a cheaper model is acceptable.

Exercise

Apply the explanation

A cheap model passes 92% of tasks at $0.001; an expensive model passes 97% at $0.004. Can you route all failures to the expensive model using these two numbers?

Read the explanation

No. You do not know failures at request time, correlation between model failures, or router accuracy. Measure a practical uncertainty/error detector and the full routed policy, including doubled latency and costs on escalations.

Lesson quiz

Check your understanding

A fallback model is accurate, but routing to it doubles latency on many requests. What should you evaluate?

Cheat sheet

Cost, tail latency, and model selection

Definition

A routing policy chooses a model using information available before the outcome is known.

Intuition

Measure the entire route, including retries and fallback calls.

Formula

Csuccess=Cinference+Cretrieval+Cretries+CoperationsNsuccessful tasksC_{\mathrm{success}}=\frac{C_{\mathrm{inference}}+C_{\mathrm{retrieval}}+C_{\mathrm{retries}}+C_{\mathrm{operations}}}{N_{\mathrm{successful\ tasks}}}

Common mistake

Knowing two models' average accuracy does not identify failures at request time.

Production notes

Trace route decisions, cost per successful task and tail latency.
