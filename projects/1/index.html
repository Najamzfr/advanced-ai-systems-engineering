Evidence-First Deep Research Platform

Research with verifiable evidence, explicit contradictions, and bounded agent execution.

Weekly milestones

Technical requirements

Deliver every canonical stage below. Use typed contracts, versioned data, automated evaluations, scoped tools, reproducible experiments, and documented failure behavior. Complexity must be justified against a simpler baseline.

System components

Keep ingestion adapters, normalized source storage, lexical/dense indexes, research planning, scoped MCP tools, evidence graph, verifier, writer, and evaluation runner independently testable. The verifier produces support labels; it does not write the report.

Data pipeline

Ingest webpages, PDFs, structured records, and repository files from a small permissioned or public snapshot. Normalize source_id, title, author, timestamp, content, URL, and trust_metadata; retain document revision and offsets. Deduplicate exact copies, reject extraction failures, index with access and time filters, and preserve raw source references for every material claim.

Agent architecture

Start with a single research agent. Compare a planner + researcher + verifier using identical tools, datasets, and budgets. A typed plan names subquestions, search strategy, required evidence, dependencies, and completion criteria. Cap steps and replans; incomplete evidence produces abstention or qualified findings.

MCP / tools

Expose scoped search_documents, fetch_document, search_web fixtures, repository lookup, and store_evidence through MCP. Validate identifiers and outputs. Restrict fetch destinations and document scope; treat extracted text as data. For a free reproducible baseline, use a frozen public-page corpus and local search instead of requiring a paid search API.

Evaluation framework

Create 80–100 questions across direct factual, multi-source, temporal, contradictory, ambiguous, missing-answer, and adversarial categories. Measure Recall@K, citation precision/completeness, unsupported-claim rate, tool selection, planner success, latency, and tokens.

Freeze the evaluation set before tuning. Include deterministic checks, human-adjudicated evidence labels, calibrated model judgment, and paired architecture comparisons. Report each category’s denominator, failures, confidence intervals where appropriate, and limitations. Keep test scenarios separate from prompt, retrieval, and training selection.

Security requirements

Separate trusted instructions from source content. Scope tool capabilities, restrict network destinations, prevent path traversal and SSRF, redact secrets, and require approval for any external publication. Include poisoned documents, malicious tool results, and unsupported citations in security tests.

Observability

Create one trace per research question with spans for planning, retrieval, reranking, each MCP call, verification, and report assembly. Record model/prompt/corpus revisions, token usage, latency, retries, evidence IDs, and support labels. Do not log credentials or private source text by default.

Deployment

Provide Docker Compose or a documented local command for the API, research worker, MCP server, evidence database, and indexes. Include deterministic fixtures, pinned dependencies, environment examples without secrets, health checks, and a complete smoke-run command. Use a small local model where feasible; disclose hardware limits and label mock runs.

Failure engineering

Inject missing PDFs, extraction corruption, unreachable sources, contradictory dates, exhausted tokens, invalid tool responses, unsupported claims, and a failed verifier. Preserve partial evidence and do not label incomplete work as verified. Re-run the same question after recovery and explain state handling.

Grading rubric

CriterionWeightEvidence for full credit
Evaluation and evidence25%Required dataset, calibrated metrics, raw results, and architecture comparisons.
System and data correctness20%Complete components, deterministic functions, provenance, and typed contracts.
Security and authorization15%Least privilege, adversarial tests, scoped tools, and approval enforcement.
Reliability and failure engineering15%Fault injection, recovery, bounded execution, and idempotent effects.
Observability and performance10%Trace coverage, latency distributions, budgets, and measured economics.
Reproduction, report, and defense15%Clean setup, complete report, clear demo, and honest limitations.

Rubric weights are course extensions. Unreproducible results or missing security/evaluation evidence do not satisfy the canonical hard pass requirements.
