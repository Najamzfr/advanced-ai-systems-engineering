GUIDED PROJECT 02 / WEEKS 05—08

Autonomous Market Intelligence & Risk Operations Platform

A complete monitoring and investigation platform with deterministic analytics and human-controlled escalation.

Business problem

A financial institution wants to continuously monitor:

  • market movements
  • company disclosures
  • news
  • anomalous price behavior
  • possible risk events

The system should:

  1. detect unusual events
  2. investigate them
  3. retrieve evidence
  4. perform deterministic calculations
  5. verify conclusions
  6. escalate only meaningful events

Weekly milestones

Technical requirements

Deliver every canonical stage below. Use typed contracts, versioned data, automated evaluations, scoped tools, reproducible experiments, and documented failure behavior. Complexity must be justified against a simpler baseline.

System components

Use an API, event bus or queue, validation layer, deterministic analytics, event router, quant and research agents, risk verifier, evidence store, approval interface, notification sink, PostgreSQL, vector index, workflow engine, OpenTelemetry collector, and Grafana. Agent recommendations never replace numeric rules or authorization.

Data pipeline

Use local replayable price/time-series fixtures plus public filings and news snapshots. Store event_time and ingestion_time, symbol, units, source_id, revision, content hash, and availability time. Validate schema, stale data, duplicates, missing intervals, and time zones. Compute returns, rolling volatility, z-scores, correlations, and volume anomalies in code using only information available at the event time.

Agent architecture

Research generates hypotheses and gathers filings, news, and historical analogues. Quant calls deterministic functions and reports numerical evidence without narrative speculation. The verifier consumes event + quant evidence + research evidence and returns severity, confidence, supporting/contradictory/missing evidence, and recommended escalation. Compare against a simpler single-agent or workflow baseline.

MCP / tools

Implement get_price_history, calculate_return, calculate_volatility, search_filings, search_news, and retrieve_company_document. Every tool is validated, authenticated, rate-limited, and logged. Authorize company/time scopes and network destinations. Return calculation inputs, units, formula version, and source revisions so outputs can be independently checked.

Evaluation framework

Create at least 150 scenarios with the exact canonical category counts: normal 30, genuine anomalies 30, misleading news 15, contradictory sources 15, missing data 15, tool failures 15, prompt attacks 15, and ambiguous cases 15.

Freeze the evaluation set before tuning. Include deterministic checks, human-adjudicated evidence labels, calibrated model judgment, and paired architecture comparisons. Report each category’s denominator, failures, confidence intervals where appropriate, and limitations. Keep test scenarios separate from prompt, retrieval, and training selection.

Security requirements

Keep monitoring read-only. Consequential report or notification actions require explicit approval bound to exact content and destination. Enforce least privilege, scoped data access, output validation, network allowlists, and redacted audit logs. Test malicious news, poisoned filings, direct/indirect injection, exfiltration, malicious MCP behavior, and excessive tool use.

Observability

Trace ingestion, anomaly_detection, agent_plan, tool:get_prices, tool:search_filings, research_agent, quant_agent, verifier, guardrail, and human_approval. Measure detection precision/recall/FPR, tool accuracy, unsupported claims, citations, p50/p95 latency, tokens, cost/request, retries, errors, and escalation. Link event, approval, and notification IDs without leaking secrets.

Deployment

Provide a local Docker Compose deployment containing API, agent service, MCP server, worker, PostgreSQL, vector database, OpenTelemetry collector, Grafana, and workflow engine. Seed deterministic scenarios, expose health checks, document migrations and secrets, and demonstrate clean startup, worker restart, and rollback. No paid cloud is required; record actual hardware requirements.

Failure engineering

Test model API failure, database failure, duplicate events, stale data, rate limits, malformed responses, and stuck workflows. Define invariants for no unauthorized action, no duplicate notification, no invented evidence, bounded execution, and correct time-series computation. Measure normal, degraded, and recovered behavior and retain the failure traces.

Rubric weights are course extensions. Unreproducible results or missing security/evaluation evidence do not satisfy the canonical hard pass requirements.
