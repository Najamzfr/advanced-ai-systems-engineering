ASSIGNMENT 07 / WEEK 07

Production Architecture RFC

Specify a production platform with durability, observability, security, scaling, and rollback.

Realistic scenario

A periodic research workflow must survive worker restarts, wait for approvals, and send exactly one intended notification per approved event.

Objective

Specify a production platform with durability, observability, security, scaling, and rollback.

Constraints

  • Assume duplicate event delivery and unknown side-effect outcomes.
  • Tie approvals to immutable action details and a validity window.
  • Keep numerical checks and authorization deterministic.

Original brief (reference only)

  • Draw component and sequence diagrams across API, queue, worker, MCP, state, approval, and notification.
  • Define SLOs, error budgets, retry/compensation rules, dead-letter handling, and scaling.
  • Describe end-to-end trace propagation and safe telemetry attributes.
  • Plan migrations, canary rollout, rollback, and recovery tests.
Original curriculum brief

Production Architecture RFC

Include:

  • component diagram
  • sequence diagram
  • failure modes
  • SLOs
  • security boundary
  • scaling strategy
  • observability
  • deployment strategy
  • rollback

Deliverables

  • RFC
  • Component and sequence diagrams
  • Failure-mode table
  • SLOs, security boundary, scaling and release plans

Submission format: a reproducible repository with the memo/report, raw evidence, diagrams, configurations, and a README linking each required item. The site tracks your completion; it does not upload or grade submissions.

Technical-defense questions

  • Where is the first durable write?
  • How does recovery distinguish not-executed from executed-but-unacknowledged?
  • Can an old approval authorize a changed report?
